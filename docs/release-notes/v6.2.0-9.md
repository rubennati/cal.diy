## Why this release matters

`v6.2.0-9` is a security maintenance release and the first image since `v6.2.0-6`. It
closes every CRITICAL finding the fork's dependency scan had open, takes the
security-relevant fixes upstream shipped between September and November 2026, and moves the
runtime off an end-of-life Node.js line.

Build numbers `-7` and `-8` were tagged but never released. Both publication runs stopped
at the same safety check: the tag-writing step wrapped the validated image in a new manifest
list, the resulting digest no longer matched the validated one, and the pipeline refused to
continue. Nothing unvalidated was announced. There is no `v6.2.0-7` image; a
`ghcr.io/rubennati/cal.diy:v6.2.0-8` tag does exist from the interrupted run, has no ARM64
counterpart, no release record and no provenance binding, and must not be deployed.
Everything those two builds were meant to carry is in this release.

## What it closes

- **Guest-email blocklist bypass.** `BLACKLISTED_GUEST_EMAILS` entries written after a
  space or a line break, in a different case, or with a `+tag` never matched, so the address
  was silently not blocked.
- **Replacement-pattern injection in custom event names.** Attendee names, host names and
  booking answers containing `$&`, `` $` ``, `$'` or `$$` were interpreted as substitution
  patterns and rewrote the event title.
- **Dependency advisories.** Next.js 16.4.3, `@sentry/nextjs` 10.75.2, `handlebars` 4.7.10,
  `next-auth` 4.24.15, `proxy-addr` 2.0.8, `shell-quote` 1.11.0, `trigger.dev` 4.5.9, and
  patched releases of `axios`, `follow-redirects`, `protobufjs`, `node-forge`, `form-data`,
  `hono`, `multer`, `vite`, `js-yaml`, `systeminformation` and `tar`.
- **End-of-life runtime.** The image now runs Node.js 22. Node.js 20, used through
  `v6.2.0-6`, stopped receiving security patches on 2026-04-30.

## What it does not claim

- The dependency scan is not clean. No CRITICAL finding remains, but HIGH findings on
  transitive packages the fork does not pin (`ws`, `@xmldom/xmldom`, `brace-expansion`,
  `fast-uri`, `uuid` and others) are still open.
- The image scan remains report-only, as documented in `SECURITY_REVIEW.md`.
- Nothing changes for PBAC or Teams: the placeholders still only fail closed (issue #13),
  and Teams remain inactive.
- Upstream's functional fixes from the same period were reviewed but not taken. That
  includes the PayPal and HitPay zero-decimal-currency fixes; operators charging in JPY, KRW
  or VND through those two apps are still affected.

## Before upgrading

- **Node.js 22** is a major interpreter change. The application code is unchanged and
  upstream runs it on Node 22, and both architectures were runtime-tested in the candidate
  run — but custom tooling that execs into the container should be checked against Node 22.
- **`BLACKLISTED_GUEST_EMAILS`** now behaves as written. Entries that never took effect
  because of whitespace, case or a `+tag` will start blocking. Review the list before
  rolling out.
- Deploy by digest, not by `latest`. The rollback target is `v6.2.0-6`.
